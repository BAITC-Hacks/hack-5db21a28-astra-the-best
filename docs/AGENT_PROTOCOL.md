# Протокол совместной работы Codex и Claude

## Взять пункт и подписаться

1. Прочитай PLAN.md, исходники ТЗ и существующие записи `coordination/claims/*.json`.
2. Выбери свободную задачу, зависимости которой имеют статус `done`. Для задач с явно указанным допуском работы на fixtures следуй допуску.
3. Выполни из PowerShell, подставив свой ID сессии:

```powershell
& D:\HackAlem\scripts\claim-task.ps1 -Task P01 -Agent Claude -Session claude-20260923-a1
```

Для Codex используй `-Agent Codex`. Session обязан отличаться у параллельных сессий одного агента.

4. Успешный вывод означает, что подпись сохранена. Скрипт использует `FileMode.CreateNew`: при одновременном захвате одного ID только один процесс создаст запись. Ошибка означает: работу не начинать, прочитать запись и выбрать другой свободный пункт. Пустая/повреждённая запись тоже считается занятой до ручного разбора.
5. Сообщи пользователю: «Взял Pxx — название. Агент: …, сессия: …, область файлов: …» и приступай только к этой области.

Скрипт предотвращает двойной захват одного ID, но не проверяет зависимости и пересечения файлов. Агент обязан проверить их сам по плану. Реестр и соблюдение протокола нужны обоим агентам: одних отметок в раздельных чатах недостаточно.

## Обновления и сдача

Запись JSON редактирует только её владелец. Сохраняй `task`, `agent`, `session`, `claimed_at`, `signature`; обновляй `updated_at` в ISO 8601 с часовым поясом, `status`, `notes`, `artifacts`, `checks`. Обновляй при завершении этапа и примерно каждые 20 минут активной работы. Пример содержимого `checks`: команда, результат, дата; не пиши «тесты прошли» без запуска.

Статусы:

- Нет записи — свободна; можно брать при выполненных зависимостях.
- `in_progress` — занята, владелец работает.
- `blocked` — занята, в `notes` указаны причина и требуемое действие.
- `review` — реализация готова, остаётся проверка; владение сохраняется.
- `done` — все критерии задачи подтверждены; результат доступен зависимым задачам.

Завершая задачу, запиши изменённые пути, проверки, ограничения и инструкции для следующего агента. Не отмечай `done`, если нужная интеграция или реальный AI-вызов ещё не проверены. При остановке оставь `blocked` с точкой продолжения.

Передача другому агенту — только после явного освобождения владельцем или решения пользователя. Сначала остановить прежнего исполнителя, сохранить прежнюю запись в `coordination/history/` с уникальным именем, затем освободить исходный файл и выполнить новый захват. Новый владелец записывает ссылку на историю. Удалять чужую запись по давности запрещено; истечение 20 минут не освобождает задачу.

## Общие файлы и разные рабочие копии

- Базовая схема — оба агента работают в `D:\HackAlem`, в непересекающихся файлах.
- `package.json`, lockfile, конфигурации и app shell меняет только владелец P02, затем P09. Другие агенты передают список нужных изменений в `notes` своей записи.
- Типы/API-контракт меняет P01 до сдачи; после сдачи изменение требует согласования с зависимыми исполнителями. Нельзя молча менять поля запроса, формулу или ID.
- До редактирования файла проверь чужие изменения. Нельзя выполнять общий reset/clean/stash, переключать ветку общей папки, удалять чужие файлы или коммитить всё командой `git add .`.
- Git/worktree разрешается организовать при реализации, если нужен. Общий реестр всегда один: `D:\HackAlem\coordination`. При смене компьютера сначала согласовать единый доступный реестр; копии JSON в разных клонах не являются блокировкой.
- Для worktree одного `done` недостаточно: в `artifacts` должен быть commit и указание, где он интегрирован. Зависимая задача начинает работу только после доступности результата в её рабочей копии.
- Отслеживай записи владения и историю в Git для аудита; актуальный реестр читается с общего диска, а не из устаревшего коммита. Git сам не предотвращает одновременный захват.

## Готовый стартовый промпт

> Работаем по D:\HackAlem\PLAN.md. Сначала прочитай AGENTS.md и docs/AGENT_PROTOCOL.md. Выбери свободную задачу с завершёнными зависимостями. До изменения файлов обязательно возьми её через scripts/claim-task.ps1, подпишись своим именем и уникальным ID сессии. Соблюдай область владения, не трогай чужие задачи и общие конфиги. Реализуй критерии готовности, выполни проверки, запиши результат и статус в общий реестр. Если задача занята, выбери другую; не перехватывай её.

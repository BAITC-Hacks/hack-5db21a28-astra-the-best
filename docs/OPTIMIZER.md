# Лучший план по Score

В редакторе города доступна отдельная кнопка **«Найти лучший план с ИИ»**. Она работает и до первого расчёта. По нажатию сервер ищет максимальный индекс качества жизни среди всех допустимых сочетаний пяти мер и назначений районов в текущем наборе данных.

Поиск учитывает бюджет, ограничения направлений, несовместимости, задержку эффекта, синергии, ограничение показателей шкалой 0–100, слабейший район и штрафы за критические значения. Равные результаты разрешаются по меньшей стоимости и стабильному порядку мер/районов. Это максимум данной учебной модели за восемь кварталов; он не означает максимума каждого отдельного показателя или прогноз реальной городской политики.

Сначала показываются пять решений, районы, стоимость, оставшийся бюджет и рассчитанный Score. Затем существующий AI-провайдер объясняет сильные стороны, риски, последствия и совет на основе фактов найденного сценария. Поиск максимума выполняется детерминированным расчётом; AI отвечает за объяснение. Ошибка AI не удаляет кандидат: объяснение можно запросить повторно, а план — применить без него.

Текущие решения не меняются при поиске. Кнопка **«Применить лучший план»** заменяет черновик найденными пятью решениями через штатный callback редактора. Старые результаты и AI-анализ сбрасываются. Затем можно рассчитать план и открыть обычный отчёт, изменить решения или сохранить вариант для сравнения.

## Реализация

- `POST /api/optimize` принимает только `datasetVersion` и `datasetHash`; устаревшие данные возвращают HTTP 409. Клиентские цены, ограничения и решения не принимаются.
- Полный поиск в `src/domain/search/optimize.ts` перебирает сочетания мер и допустимые районные назначения. Повторяющиеся локальные расчёты переиспользуются, итог заново рассчитывается каноническим `simulate`.
- Ответ содержит `datasetVersion`, `datasetHash`, `method: "exhaustive"`, `checkedCandidates` (число допустимых полных сценариев) и `simulation`.
- Сервер переиспользует результат для той же версии/hash данных. Неуспешный расчёт не сохраняется в кеше.
- После поиска UI вызывает существующий `POST /api/analyze`. Подтверждение чисел и ссылок на факты, модель и ограничения запросов остаются прежними.
- Старый поиск улучшения заменой одной меры в сравнении сценариев остаётся доступен отдельно.

## Проверенный результат текущего набора

Для `astana-s2-v1` полный поиск проверил 694 395 допустимых сценариев. Максимум — **57,236735** (в UI **57,24**), стоимость **9,8 млрд ₸**, остаток **200 млн ₸**:

- M2 — умные светофоры, весь город;
- M3 — линия ЛРТ / расширение, Нура;
- M8 — центр семейного здоровья / поликлиника, Нура;
- M9 — дворовые спорт-хабы, Нура;
- M14 — аварийные бригады ЖКХ и раннее оповещение, весь город.

Обычный `/api/simulate` независимо подтвердил те же решения и Score. Реальный `/api/analyze` вернул соответствующий этому сценарию отчёт от GPT-6 Luna с 109 фактами.

Результаты остальных фактических проверок фиксируются в `coordination/claims/P29.json`, `P30.json` и `P31.json`.

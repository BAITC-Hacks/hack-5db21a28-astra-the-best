# География и права на карту

Снимок границ: 23 сентября 2026 года. Карта использует реальную географическую основу Астаны, а показатели, население и эффекты мероприятий — синтетические числа из ТЗ. Цвет игровых зон нельзя трактовать как реальные районные измерения.

## Файлы

- `public/geo/astana-osm-source.json` — сохранённый ответ OpenStreetMap Nominatim Lookup с границей города и шестью текущими административными районами.
- `public/geo/astana-game-zones.geojson` — пять непересекающихся зон симулятора, созданных `scripts/build-geo.py`. ID соответствуют `src/contracts/index.ts`: `esil`, `almaty`, `saryarka`, `baikonur`, `nura`.
- `bbox` в итоговом GeoJSON: `[71.217973, 50.857608, 71.785191, 51.35111]` (запад, юг, восток, север). Это вся административная территория Астаны в снимке OSM, включая отдалённые участки. Начальная камера должна охватывать bbox; пользователь может приблизить центр города.

Оригинальный запрос: `https://nominatim.openstreetmap.org/lookup?format=json&polygon_geojson=1&osm_ids=R3087155,R3479876,R3482819,R3486954,R8593081,R20593940,R19733918`. Ответ сохранён локально, поэтому приложение не обращается к Nominatim при каждом запуске. [Правила публичного Nominatim](https://operations.osmfoundation.org/policies/nominatim/) ограничивают автоматические обращения и требуют атрибуции.

| Зона игры | OSM relation | Преобразование |
|---|---:|---|
| Есиль | 3479876 | Вычтен район Нура 20593940: исходный полигон OSM заметно перекрывает его |
| Алматы | 3482819 + 19733918 | Объединены нынешние Алматы и Сарайшык для модели ТЗ с пятью районами |
| Сарыарка | 3486954 | Геометрия источника, пересечения на границах устранены |
| Байконур | 8593081 | Геометрия источника, пересечения на границах устранены |
| Нура | 20593940 | Геометрия источника |

Городская граница — relation 3087155. Все зоны ограничены ею. На входе валидны все семь полигонов. У шести районных полигонов было существенное перекрытие Есиль/Нура (около 23,5% площади городской геометрии в координатном расчёте), поэтому называть их готовым официальным слоем нельзя. Скрипт явно отдаёт эту область Нуре; микропересечения на границах устраняются по порядку зон. Итоговая площадь зон покрывает город с относительной разницей меньше `1e-6`, зоны не пересекаются и геометрии валидны. Это **игровое сопоставление**, а не актуальная официальная карта районов.

[План развития города на 2026–2030 годы](https://www.gov.kz/memleket/entities/astana/documents/details/940185?lang=ru) перечисляет шесть современных районов, включая Сарайшык. В исходном ТЗ симулятора перечислено пять. Сведения о выделении Сарайшыка из южной части Алматы приведены в [материале о создании района](https://krisha.kz/content/news/2024/2024-v-astane-poyavitsya-shestoy-rayon-sarayshyk). Объединение позволяет показывать весь город без шестого синтетического набора показателей.

## Лицензии и обязательные подписи

Геоданные OpenStreetMap предоставляются по [ODbL 1.0](https://www.openstreetmap.org/copyright). Для карты и распространяемой преобразованной геометрии сохранить подпись `© OpenStreetMap contributors` и ссылку на лицензию. Производный GeoJSON публикуется с теми же условиями ODbL; исходные OSM ID и описанное преобразование помогают восстановить его происхождение. Указание авторства обязательно, поэтому эти данные не CC0.

Подложка: [OpenFreeMap](https://openfreemap.org/) через MapLibre. Публичные тайлы доступны бесплатно, без ключа; условия сервиса и лицензию проверить перед публичной демонстрацией. OpenFreeMap требует атрибуцию OpenMapTiles/OpenStreetMap; MapLibre обычно отображает её из стиля, но P13 обязан проверить видимость в приложении и сохранить ссылку на ODbL. Дополнительные 3D-ассеты P14 должны иметь собственные лицензии, проверенные отдельно; бесплатность скачивания сама по себе не означает свободное использование.

## Воспроизведение

При установленном Python и Shapely запустить из корня проекта:

```powershell
python -m pip install shapely
python scripts/build-geo.py
```

Скрипт использует сохранённый снимок, не делает сетевых запросов и выдаёт детерминированный GeoJSON. При обновлении исходных OSM границ сохранить новый датированный снимок, повторить проверку топологии и только затем заменить файл. Новая геометрия не должна менять экономическую модель или формулу Score.

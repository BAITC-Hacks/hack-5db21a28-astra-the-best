# Решения P01 — контракт v1

Основание: PLAN.md версии 2 и прочитанные локальные снимки S1, S2, S3 в docs/sources. Контракт определён в src/contracts/index.ts; HTTP-поведение — docs/API.md. Владелец P01: CodexCLI-SecondAccount, сессия codex-second-d550bee90cfa40edbf3c3098c5ff5ac3.

## Правила и трактовки

- Применяем подробные правила S2: бюджет 100, ровно пять уникальных measureId, максимум две меры направления; следовательно, минимум три направления. Все пять направлений доступны. Остаток не даёт бонуса.
- Вопрос организаторам для пользователя: «Верно ли, что по S2 разрешено выбрать пять мер минимум из трёх направлений, максимум две на направление, и не требуется по одной мере каждого из пяти направлений?» Ответ пока не получен; самостоятельно вопрос не отправлялся. Работа продолжается по S2.
- ID районов: esil = Есиль, almaty = Алматы, saryarka = Сарыарка, baikonur = Байконур, nura = Нура. Порядок канонический именно такой. Направления transport, ecology, social, safety, services. Меры M1–M14 и индикаторы T1,T2,E1,E2,S1,S2,B1,B2,C1,C2 неизменны.
- Данные синтетические; все показатели уже направлены «больше — лучше». Повторной инверсии нет. Все числа S2 переносятся без балансировки.
- Горизонт восемь кварталов. Сначала суммируются эффекты с долей (8−L)/8 и фиксированные синергии, затем один clip каждого показателя в [0,100]. Городская мера стоит один раз и действует во всех пяти районах.
- Синергии: M1+M2 → T1 +2 в районе M1; M10+M12 → B1 +2 в районе M10; M5+M6 → E2 +2 в районе M5. Не масштабируются лагом и не дублируются.
- Конфликты: M1+M3 везде; M4+M7 и M5+M13 только при совпадении района.
- D = сумма весов показателей. Веса: 0.10,0.10,0.09,0.11,0.11,0.11,0.09,0.09,0.10,0.10. Доли населения: 0.27,0.24,0.20,0.13,0.16. Score = 0.7 × средневзвешенный D + 0.3 × min D − число показателей строго <40.
- Промежуточного округления нет, финальный Score не обрезается. UI отображает два знака. Минимум при равенстве перечисляет все районы в каноническом порядке. Числовая погрешность тестов ≤1e−8.
- База: Score 52.55768, среднее 56.8624, минимум 49.18, два критических показателя. База справочная, не финальная заявка.
- Контроль: M7/M8/M10 в Нуре, M12 город, M5 в Сарыарке → стоимость 95, Score 56.54307, дельта 3.98539. Дешёвый пример M9/M11/M10/M4 в Нуре + M12 город стоит 61; районные назначения выбраны явно для воспроизводимости.
- Ledger хранит вклад по индикаторам до clipping, синергии отдельно и итог всех 50 показателей. Аддитивный вклад в Score не заявляется: минимум, clipping и порог нелинейны.
- Черновик 0–5 мер допустим при соблюдении прочих правил. Финализация только ровно пяти. Лишние поля, null вместо района, неизвестные ID и район у городской меры отклоняются, а не исправляются молча.

## AI и инфраструктура

- AI объясняет серверный результат, не считает Score. Обязательны сильные стороны, риски, последствия и хотя бы один совет. Текст на русском, числовые факты показываются через ссылки на серверный facts. Ошибка AI не уничтожает расчёт.
- На проверке окружения 23.09.2026 переменные OPENAI_API_KEY, OPENAI_MODEL, NVIDIA_API_KEY, AI_API_KEY, AI_MODEL отсутствуют; значения секретов не читались в вывод. Файл активации из S3 не предоставлен. Реальный провайдер и модель ещё не подтверждены; P06 нельзя закрывать без реального успешного вызова.
- Предусмотрены серверные AI_API_KEY, AI_BASE_URL, AI_MODEL (провайдер с совместимым chat/completions API); проверенный провайдер/модель будут записаны в P06 claim. Ключ не передаётся клиенту. Математическое ядро доступно без ключа.
- Runtime найден: Node 22.14.0, npm 10.9.2. P02 фиксирует зависимости и lockfile; для всех веток нужны next, react, react-dom, zod, maplibre-gl; dev: TypeScript, Vitest, Playwright, ESLint, React Testing Library, jsdom, типы React/Node/GeoJSON.
- Git-репозиторий и remote пока отсутствуют. Push, публикация и сдача запрещены текущим запросом. Фактический дедлайн запрошен, ответа пока нет; пятичасовой срок S3 не трактуется как известное время окончания.

## Полная карта и интеграция

- Вся Астана сразу на MapLibre/OpenFreeMap обязательна. Пять зон модели и их географическое сопоставление документирует отдельная P15 (добавлена владельцем плана во время P01); P13 использует её геометрию. Нельзя добавлять шестой район или выдавать условные зоны за официальные. Атрибуция обязательна.
- CityViewProps фиксирует общие входы карты и эффектов. Координаты и камера не входят в ScenarioRequest и не влияют на расчёт. preview — только иллюстративная выбранная мера, не валидный расчёт сценария. После изменения decisions интегратор сбрасывает result/AI или скрывает их до совпадения scenarioId.
- Слой направления отображает взвешенное среднее двух индикаторов, нормированное суммой их весов в шкалу 0–100. Слой индикатора использует исходный показатель 0–100. Это визуальное агрегирование, не другая формула Score.
- Город и отчёт используют одно состояние; camera сохраняется, active=false останавливает декоративную анимацию. До/после использует baseline/result сервера. Черновые объекты явно отмечаются, географическое положение иллюстративно.
- Backend-поток этой сессии: P01–P06. P07/P08/P09/P10/P11/P13/P14 зарезервированы за другим агентом. Общие конфиги после завершения P02 передаются P09; последующие изменения согласуются через claim notes. Контракт после done P01 меняется только с согласованием зависимых владельцев.
